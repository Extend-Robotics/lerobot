# Connecting BiPico4 to the Tianji arms

**Recommendation.** Keep the G1D integration's input and operator controls. Use Tianji-specific forward and inverse kinematics to turn clutch-relative wrist motion into the 14 joint targets that the existing LeRobot Tianji driver accepts. Wuji provides a reference for the arm frames, units and solver. Its live elbow tracking needs two sensors that handheld controllers alone cannot supply.

This is a source review of the local LeRobot working tree (base `a23d040c`, including the locally added `tianji` driver) and [Wuji revision 6478013](https://github.com/wuji-technology/wuji-hand-teleop/tree/647801345a6a27dec5cbf56280ce63bb8b2f6a32). All rates below are configured rates. Hardware motion, timing and model compatibility remain unverified.

| Arm-control decision | Local G1D + BiPico4 | Wuji PICO + Tianji |
|---|---|---|
| What the operator wears | Headset and two handheld controllers | Headset and four serial-mapped trackers, one wrist and one forearm per side |
| What defines “forward” | Current headset yaw in robot coordinates | Fixed tracking-world alignment and a different chest basis for each arm |
| When following begins | Independently on each grip press, anchored to measured wrist pose | After the robot moves to configured start joints and tracker baselines are captured |
| Where the elbow goes | The G1 bimanual IK objective resolves redundancy | Forearm geometry supplies a preferred elbow direction to each Tianji solve |
| What reaches hardware | Fourteen G1 joint targets in radians through the Unitree command path | Up to two seven-joint position targets in degrees, tracked in Marvin joint impedance mode (state 3, impedance type 1) |

## G1D on the standard LeRobot path

1. The G1D preset selects `bi_pico4.output_mode="xr"`. BiPico4 reads headset and both controller poses (metres, quaternion `xyzw`), grips, triggers and the XRoboToolkit timestamp. It checks that the sample is coherent and the source clock advances. The default BiPico4 Cartesian mode instead emits per-side TCP and gripper fields. Neither raw schema is itself a Tianji joint action. [Input implementation](../../src/lerobot/teleoperators/bi_pico4/bi_pico4.py) · [G1D preset](../../configs/unitree_g1_pico.json)
2. The processor changes XR axes to robot axes as `(-z, -x, y)`, subtracts headset position and removes headset yaw. It then adds the G1 head-to-waist offset of 0.15 m forward and 0.45 m up. Moving the head relative to a stationary controller can therefore change an engaged wrist target. [XR mapping](../../src/lerobot/teleoperators/bi_pico4/xr_mapping.py)
3. Each grip has hysteresis (engage above 0.5, release at or below 0.3 by default). On engagement, FK of the measured joints supplies separate translation and rotation offsets, and that tick outputs measured joints. On release, the processor latches that arm's measured joints. The operator can reposition a controller and re-grip without commanding a jump. The setup guide's description of resuming without rebasing conflicts with the current processor. [Processor](../../src/lerobot/teleoperators/bi_pico4/g1_processor.py) · [Setup guide, section 8](../unitree_g1d/PICO_G1D_TELEOPERATE_SETUP.md)
4. The processor solves both wrist targets with the G1-29 Pinocchio/CasADi model using measured joints, checks solve status, finite values, joint bounds and sample age, then copies results only for active arms. The robot applies its own measured-joint step limit (default 0.12 rad) and the G1D deployment bridges commands to Unitree DDS. Triggers optionally control Revo2 hands independently of the arm clutch. The processor also exposes grip and clutch as recording metadata. [G1 solver](../../src/lerobot/robots/unitree_g1/g1_kinematics.py) · [Processor selection and timeout](../../src/lerobot/processor/factory.py) · [G1D arm transport](../unitree_g1d/ARM_COMMUNICATION.md)

## How Wuji drives Tianji

Wuji has separate arm paths for PICO and HTC Vive. The Vive path uses SteamVR and `tianji_output`. The PICO path uses `pico_input` and `tianji_world_output`. Glove-to-finger retargeting is separate from both. [PICO guide][pico] · [SteamVR guide][vive]

**Startup and wrist tracking.** The output node first moves the robot to configured initial joint angles. The input node captures tracker poses on initialization (manual service or a five-second delay in the template). Wrist displacement since initialization is added to the configured initial end-effector position. Wrist rotation since initialization is expressed in the arm basis and applied to the initial tool orientation. One-Euro filters smooth position and orientation. The HMD pose serves visualization. This gives continuous following from one reference pose, with no handheld per-arm clutch in this path. [Input configuration][inputconfig] · [Incremental mapping][mapping] · [Output node][output]

**Frames.** Both systems map XR vector components to world as `(-z, -x, y)`. Wuji then maps a world displacement `(x, y, z)` to left chest `(x, -z, y)` or right chest `(x, z, -y)`. For example, lifting both wrists produces a negative left-chest Y displacement and a positive right-chest Y displacement. Despite the package name, the output node expects each wrist target already expressed in its own chest frame. Applying that rotation twice would send the arms along the wrong axes. [Robot configuration][config] · [Incremental mapping][mapping] · [Pose callbacks][output]

**Elbow tracking.** A wrist pose constrains six degrees of freedom on a seven-joint arm. Wuji estimates the remaining posture from the forearm tracker by projecting its position onto the shoulder-to-wrist line and using the perpendicular offset as an elbow direction. It constrains and filters this direction and retains a previous or default direction when the geometry becomes degenerate. ROS carries the wrist and elbow separately on `/{side}_arm_target_pose` and `/{side}_arm_elbow_direction`. [Elbow calculation][mapping] · [Topic publication][inputnode]

**IK and output.** The output loop (90 Hz by default) uses the latest pose and direction per side. It converts pose-matrix translations from metres to millimetres and runs Marvin IK separately for A/left and B/right with the M6 configuration. Each solve uses the last successful joint vector as a seed, tries the elbow constraint first, then retries in seed-proximity mode (`zsp_type=0`). Failed or out-of-range solutions are discarded for that side. The other side can still command. The output node caches poses and its control loop has no per-pose expiry check, so loss of input publications alone does not clear the last target. [Solver and dispatch][solver] · [Output loop][output]

## What the existing Tianji driver needs

The local robot already exposes measured and commanded `left_joint_1.pos` through `right_joint_7.pos`, in degrees, and sends both arms over Ethernet. Connection acquires feedback. A separate `enable_position_control()` call seeds both arms from measurement and requests position-follow mode. Every `send_action()` requires all 14 finite targets, checks arm state and the feedback frame pair, and rejects the whole action if any target differs from measurement by more than 2° by default. The current processor factory selects a Pico joint mapper only for G1, and the Tianji sine diagnostic is the existing caller that explicitly enables position control. Pairing the current robot and teleoperator by configuration alone leaves both the conversion and arming steps unresolved. [Tianji driver](../../src/lerobot/robots/tianji/tianji.py) · [Sine diagnostic](../../src/lerobot/robots/tianji/check_sine.py) · [Processor factory](../../src/lerobot/processor/factory.py)

| Proposed integration choice | Reason and verification |
|---|---|
| Reuse BiPico4 XR sampling and implement a Tianji processor taking the action plus measured observation. | Preserve timestamp checks, independent grips and measured-pose rebasing. Keep one hardware writer in the existing robot driver. Output exactly its 14 degree-valued keys, including held joints on the released side. |
| Start with wrist motion in a fixed world frame and per-side chest transforms. | This matches Wuji's fixed-base geometry while retaining the local clutch. Anchor translation and orientation to measured Tianji FK on each press. Check controller-only motion along three axes, in-place rotation, head-only motion and release/re-grip in replay. |
| Evaluate Marvin seed-proximity IK for controller-only operation. | Two controllers do not measure elbows. Wuji's fallback is a candidate for posture continuity, but routine use as the primary solve needs testing near extension and across re-grips. Verify the installed arm model, tool frame, native library compatibility and FK→IK round trips first. The local driver bundles the communication SDK. Wuji's kinematics wrapper, `libKine.so` and model configuration are additional dependencies. [Kinematics assets][assets] · [Model configuration][config] |
| Keep explicit arming and the driver's measured-joint bound. | Integrate arming into the intended teleoperate/record lifecycle. Define what happens on stale input, failed IK or a too-large candidate before sending either arm. Wuji can omit one arm from a write, whereas LeRobot requires a complete pair. Exercise those cases and check the final command against the measured 2° envelope in an offline preview before hardware commissioning. |
